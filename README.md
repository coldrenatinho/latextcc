# ❓ Problema de pesquisa

Sistemas de gestão de estoque são utilizados para organizar produtos, registrar movimentações e fornecer informações relacionadas à disponibilidade de recursos. Entretanto, diferentes organizações apresentam necessidades, restrições e níveis de complexidade distintos.

Nesse contexto, torna-se relevante investigar quais demandas podem orientar o desenvolvimento de uma solução de gestão de estoque e de que maneira requisitos, tecnologias, arquitetura e características de qualidade podem ser considerados durante a construção dessa solução.

A pesquisa utiliza o **Estoque Fácil** como objeto de estudo desse processo.

## Questão de pesquisa

> **Como projetar e desenvolver um sistema web para gestão e controle de estoques a partir de demandas identificadas no mercado, justificando as decisões tecnológicas e arquiteturais adotadas e avaliando suas características com base em critérios de qualidade de software?**

---

# 💡 Hipótese / pressuposto

Parte-se do pressuposto de que a identificação prévia de demandas, aliada à aplicação de princípios de engenharia de software e à escolha fundamentada de tecnologias e decisões arquiteturais, pode contribuir para o desenvolvimento de uma solução de gestão de estoque adequada aos requisitos definidos para seu contexto de utilização.

A pesquisa buscará avaliar esse pressuposto durante o desenvolvimento e análise do Estoque Fácil.

---

# 🎯 Objetivo geral

> **Projetar, desenvolver e avaliar o software Estoque Fácil, um sistema web para gestão e controle de estoques, a partir da identificação de demandas relacionadas ao domínio, justificando as decisões tecnológicas e arquiteturais adotadas e analisando suas características segundo critérios de qualidade de software.**

# 🎯 Objetivos específicos

1. Investigar problemas e necessidades relacionados à gestão e ao controle de estoques;
2. realizar levantamento bibliográfico sobre gestão de estoques, sistemas de informação, engenharia e qualidade de software;
3. identificar e analisar soluções de gestão de estoque existentes;

7. desenvolver as funcionalidades definidas para o sistema;
8. documentar as principais decisões arquiteturais adotadas durante o desenvolvimento;
9. estabelecer critérios para avaliação da qualidade do software;
10. avaliar o sistema desenvolvido;
11. comparar características selecionadas do Estoque Fácil com soluções existentes;
12. identificar limitações e possibilidades de evolução do projeto.

# ✅ Justificativa

A gestão adequada de estoques possui importância para organizações que dependem do controle de produtos, materiais e outros recursos. Sistemas de informação podem contribuir para centralizar registros, melhorar a rastreabilidade das movimentações e disponibilizar informações para acompanhamento e tomada de decisão.

O desenvolvimento do Estoque Fácil possibilita estudar esse problema sob a perspectiva de Sistemas de Informação e Engenharia de Software, relacionando necessidades do domínio com requisitos, arquitetura, tecnologias e qualidade do produto desenvolvido.

Do ponto de vista acadêmico, o trabalho permite documentar e analisar todo o processo de desenvolvimento de uma aplicação web real, evitando limitar a pesquisa à implementação do software.

A análise de soluções existentes também permitirá identificar características recorrentes, limitações e oportunidades que possam fundamentar os requisitos do sistema.

# 🏗️ Projeto e arquitetura

Após a definição dos requisitos, serão documentadas as decisões relacionadas à arquitetura da aplicação.

A arquitetura implementada e documentada no repositório utiliza:

```text
Navegador
Jinja2 + Bootstrap 5
        │
        │ HTTP / HTML
        ▼
Aplicação server-rendered
Python 3.13 + FastAPI + Uvicorn
        │
        ▼
Persistência
SQLAlchemy
        │
        └── PostgreSQL — desenvolvimento e produção
```

Também poderão ser analisadas tecnologias relacionadas à infraestrutura da aplicação:

```text
GitHub
   │
GitHub Actions
   │
GitHub Container Registry
   │
Docker / Docker Compose + PostgreSQL
   │
Traefik
   │
Amazon EC2
```

A pesquisa não pretende apenas relacionar as tecnologias utilizadas, mas **documentar os motivos que fundamentaram suas escolhas**, suas vantagens, limitações e adequação aos requisitos do projeto. Python e FastAPI concentram as regras e rotas em uma linguagem com amplo ecossistema; SQLAlchemy organiza a camada de persistência; PostgreSQL, utilizado em ambos os ambientes, reduz diferenças de comportamento e atende ao uso concorrente e à integridade das movimentações; Jinja2 e Bootstrap reduzem a complexidade de uma interface interna baseada em formulários; OpenPyXL permite exportações em XLSX; e Docker Compose torna o ambiente reconstruível. GitHub Actions, o registro de imagens, EC2 e Traefik apoiam uma implantação automatizada com separação de ambientes e HTTPS.

## Fluxo de desenvolvimento e entrega

O trabalho será organizado pelo seguinte fluxo:

1. abertura de uma **issue** para registrar a funcionalidade, correção ou tarefa;
2. criação de uma branch específica para implementar a demanda;
3. abertura de **pull request** para a branch `developer`;
4. revisão e aceite do merge;
5. execução de análises e testes no ambiente de desenvolvimento/homologação;
6. promoção da versão validada para a branch `main`, correspondente à produção.

O GitHub Actions constrói a imagem Docker, publica-a no GitHub Container Registry e configura a implantação com os segredos do ambiente. O arquivo `docker-compose.yml` atende à execução local; o arquivo `docker-compose.prod.yml`, parametrizado pela imagem publicada, é empregado nas pilhas remotas de desenvolvimento/homologação e produção. As duas pilhas utilizam PostgreSQL, mas mantêm projetos Compose, credenciais, bancos e volumes independentes.

Na versão do workflow consultada para o TCC, o gatilho ainda referencia `develop`, apesar de a configuração interna também reconhecer `developer`. O alinhamento do gatilho e a inclusão de etapas explícitas de análise e testes são atividades previstas, não resultados já concluídos.
